# ИС поддержки организации мероприятий

Проект информационной системы для поддержки организации и проведения мероприятий сборной по чирлидингу и чир спорту. Основу системы составляет реляционная база данных PostgreSQL, реализованная в Supabase.

Система предназначена для централизованного учёта участниц, мероприятий, регистраций, сотрудников, документов, взносов и реквизита. Реализованы SQL-запросы для получения сводной информации, а также процедуры и триггеры для выполнения типовых операций и проверки данных. Пользовательский интерфейс в рамках проекта не разрабатывался.

## Актуальность и цель проекта

Ручная организация спортивных мероприятий требует обработки большого количества взаимосвязанных сведений. При ведении учёта в отдельных таблицах и документах возникают следующие проблемы:

- дублирование и несогласованность данных;
- риск ошибок при регистрации участниц и учёте взносов;
- сложности с координацией сотрудников и необходимых ресурсов;
- трудоёмкость подготовки сводной и аналитической отчётности.

**Цель проекта** — создать единую базу данных для поддержки организации мероприятий, сократить объём ручной обработки информации и обеспечить удобный доступ к сведениям, необходимым для координации команды и принятия организационных решений.

## Технологии

- **PostgreSQL, Supabase** — хранение данных и администрирование базы.
- **SQL** — выборки, соединение таблиц, группировки, представления и аналитические расчёты.
- **PL/pgSQL** — хранимые процедуры и триггерные функции.
- **ERwin, IDEF0, IDEF1** — моделирование процессов и структуры данных.
- **Supabase CLI, Docker, Git, GitHub** — экспорт и публикация проекта.

## Структура базы данных

В базе данных созданы семь таблиц:

| Таблица | Назначение |
| --- | --- |
| `участники` | Данные участниц, контактная информация, страховки и размеры взносов |
| `мероприятия` | Названия, даты и места проведения мероприятий |
| `регистрация_участников` | Регистрации, статусы участия и отметки об оплате |
| `сотрудники` | Сведения об ответственных сотрудниках |
| `пакет_документов` | Документы для организации мероприятий, включая выездные соревнования |
| `реквизит` | Наименование, количество и стоимость используемого реквизита |
| `организация_мероприятий` | Связь регистраций с сотрудниками, документами, реквизитом и бюджетом |

Связи между таблицами реализованы с помощью первичных и внешних ключей. Участница может зарегистрироваться на несколько мероприятий. Данные об организации связаны с мероприятием через соответствующую регистрацию.

База заполнена вымышленными демонстрационными данными, в том числе о 25 участницах, 8 мероприятиях и 4 сотрудниках. Также добавлены регистрации, документы и реквизит, характерные для соревнований и выездов команды.

## Реализованные SQL-механизмы

**Представления (4):**

- `список_регистраций` — сведения об участницах и их регистрациях;
- `неоплаченные_взносы` — регистрации с неоплаченными взносами;
- `документы_выездных_мероприятий` — документы одного выездного соревнования по ответственным сотрудникам;
- `анализ_взносов_по_мероприятиям` — количество участниц, минимальные, максимальные и средние взносы, а также полученные суммы.

**Хранимые процедуры (3):**

- `отметить_оплату_взноса` — отметка об оплате с проверкой регистрации;
- `изменить_статус_регистрации` — изменение статуса с проверкой допустимых значений;
- `зарегистрировать_участницу` — создание регистрации с проверкой существования записей и отсутствия дубликата.

**Триггеры (2):**

- `триггер_повторной_регистрации` — предотвращение повторной регистрации на одно мероприятие;
- `триггер_проверки_реквизита` — проверка неотрицательных значений количества и цены.

В SQL-запросах применяются `JOIN`, `WHERE`, `GROUP BY`, `DISTINCT`, подзапросы и агрегатные функции (`COUNT`, `SUM`, `AVG`, `MIN`, `MAX`, `STRING_AGG`).

## Содержимое репозитория

- `База_данных/Структура_БД.sql` — структура таблиц, ключи, представления, процедуры и триггеры.
- `База_данных/Тестовые_данные.sql` — демонстрационные данные, выгруженные из Supabase.
- `SQL-запросы/Представления/` — отдельные SQL-файлы представлений.
- `SQL-запросы/Процедуры/` — отдельные SQL-файлы процедур.
- `SQL-запросы/Триггеры/` — отдельные SQL-файлы триггеров.
- `Диаграммы/` — модели IDEF0 и IDEF1, а также схема базы данных.

## Восстановление базы данных

Для восстановления потребуется PostgreSQL и утилита `psql`. Создайте пустую базу, затем последовательно выполните команды из корневой папки репозитория:

```powershell
psql -X -v ON_ERROR_STOP=1 --dbname "СТРОКА_ПОДКЛЮЧЕНИЯ" --file "База_данных/Структура_БД.sql"
psql -X -v ON_ERROR_STOP=1 --dbname "СТРОКА_ПОДКЛЮЧЕНИЯ" --file "База_данных/Тестовые_данные.sql"
```

Экспорт подготовлен в Supabase. При восстановлении в другой среде PostgreSQL может потребоваться адаптировать команды, связанные с ролями и правами доступа. Не выполняйте восстановление поверх действующей базы с данными.

## Примечание

Проект носит учебный характер и демонстрирует проектирование реляционной базы данных и применение SQL для поддержки организационных процессов. Все персональные сведения и записи о мероприятиях в демонстрационном наборе вымышлены. Для реальной эксплуатации потребуются дополнительные настройки доступа и развитие модели учёта платежей.
